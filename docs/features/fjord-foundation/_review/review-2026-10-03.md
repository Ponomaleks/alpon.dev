## Design-match gap on the Not-found page (Owner, 2026-10-03)

Found by the Owner after this review; neither reviewer caught it. The page matches the design-system component demo (`components/feedback/NotFound.jsx`) but not the page design in `design/handoff/site` (`Misc.jsx` 404 screen, `design/screenshots/{dag,natt}_not_found_*.png`): the map panel is missing, the layout is one column instead of two, the heading is "Page not found" instead of "This page is off the map.", and the code line uses "·" instead of "/".

- **Resolution:** not rebuilt in this feature. Deferred as spec §8 OQ-02 (owner Alexander Ponomarenko, due step 3), added to the roadmap step 3 scope, and added to the PR's design-deviation list at ship together with S2-13.
- **Root cause:** the sources of truth did not separate page designs from components. `CLAUDE.md` named `design/handoff/` as one source, `docs/design-system.md` said NotFound was "built as `src/pages/404.astro`", and `screens.md` listed the component files first, so the spec, the screen manifest and the reviews all compared the page with the component demo. The site also bundles a newer copy of the design system (`design/handoff/site/project/_ds/`) whose NotFound has the map panel, while `design/handoff/design-system/` holds the older one. The spec's "Design match" NFR ("0 undocumented differences") was therefore checked against the wrong reference, although `design/screenshots/` already held the page-design screenshots.
- **Fix of the cause (same commit):** `CLAUDE.md` §Sources of truth and `docs/design-system.md` now put the page designs in `design/handoff/site/` above the design-system components; every `screens.md` screen cites its page design as the primary reference; the "Design match" review compares against `design/screenshots/`. The NotFound inventory row is corrected; no other inventory row equates a component with a page.
- **For the re-review:** the Design match NFR is met only through the documented deviations (OQ-02 plus the three intentional ones); check the PR list against the screenshots.

- **Line endings:** with `core.autocrlf=true`, cherry-picked files arrive with CRLF in the working copy and fail `prettier --check`, while the index holds LF. The working copies were converted back to LF before the gate. The same effect made `npm run lint` exit 1 inside the agents' worktrees.
