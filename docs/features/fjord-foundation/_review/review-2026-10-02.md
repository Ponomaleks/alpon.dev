### Resolution details

**F-01 — visual baselines.**
- Add a manually triggered workflow (`workflow_dispatch`). It builds the site, runs the visual suite in the official Playwright Docker image with snapshot update, and uploads the PNGs as an artifact.
- The Owner reviews the PNGs against the design before they are committed.
- After that, remove `continue-on-error`. A missing baseline fails CI instead of skipping.

**F-02 — warning contrast pair.**
- Add both pairs to the manifest. The test asserts the warning pair as a named known failure.
- The contrast check prints the known failure on every run: pair, theme, ratio, and "known failure, fix before step 7 Callout".
- The token fix itself is deferred to spec §8 OQ-01 (owner Alexander Ponomarenko, due before step 7). The Owner darkens the Dag warning color in Claude Design and re-exports; the pair then moves to the normal passing pairs.

**F-06 — CSP audit.**
- Parse the built HTML with a real HTML parser instead of regexes. Add parse5 or htmlparser2 as a devDependency and explain why in the PR.
- Keep the three reported cases as Vitest fixtures: `data-src=`, `data-type=`, and `>` inside an attribute value.

**F-09 — token-only lint.**
- Cover the shorthands (`transition`, `animation`, `font`, `border`, `outline`, `box-shadow`), the size properties, and the inset properties (`top`/`right`/`bottom`/`left`).
- Disallow `pt` and the other absolute units. Allow viewport units only where layout needs them (for example `min-height: 100dvh`), through an allowlist rather than everywhere.
- Check that every `var(--fjord-*)` used is declared in `tokens.css`, and fix the fixture.
- Add a fixture for each new case.

**F-15 — reduced-motion generator.**
- Throw when a matched token is not a plain number, and anchor the pattern to motion token names.
- Decide scale tokens by how the handoff uses them: a factor in `scale(var(...))` resets to `1`; a delta added to 1 resets to `0`.
- Add a unit test that no reduced-motion token can make an element invisible.

**F-17 — CRLF-safe hash.**
- Normalise the bootstrap text once when it is read, and use that same string for both the inline `<script>` and the hash. The audit keeps hashing the exact text found in the built HTML.
- Add `.gitattributes` with `src/scripts/*.js text eol=lf`.
- Add a Vitest case where the source has CRLF line endings and the build still matches.
